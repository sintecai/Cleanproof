# Customer visibility restoration

The web customer entry no longer renders the dedicated "CleanProof is locked" screen or its Resume securely button. On backgrounding it hides the workspace, fences in-flight opening work, clears in-memory workspace access and locks the in-memory session. On foregrounding it attempts to restore the same account, revalidates the server user and membership and then opens the account workspace. A session failure leads to the existing sign-in form; a workspace or network error remains actionable without deleting durable data. Existing account forms and their policies are unchanged. The earlier sparkle branding and prepared PDF changes remain in the source.

This addresses a code path that can trigger when reports change tab visibility, but the user's authenticated report-to-return sequence was not reproduced. No browser acceptance, live session-expiry or sign-out test was completed against this revision. Connected staging remains version 27 and has not been updated. The original browser's device-only work has not been backed up; a protected backup is required by the user before deployment to that origin. Host tests, a source-level regression and connected web build passed; native and real-browser acceptance remain open.
